# Readability and House Style

Review code as a maintainer who wants it to feel native to the repository. Find
hand-written behavior where a repository utility already exists, dependency
inversions, needless branches or wrappers, inconsistent naming and output
idioms, and comments that fail to explain an invariant.

Use local precedent rather than generic preference. Do not report a formatter
nit or subjective taste. Do not demand an abstraction for similar blocks when
keeping their distinct semantics local is clearer. Treat documented product
requirements and intentional exceptions as constraints, not style defects.
