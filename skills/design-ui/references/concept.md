# Concept and alternatives

Run after core step 1 and any reference research, for a new surface, an open visual direction, or a redesign. It ends with the composition core step 2 refines.

## Find the idea

Write one sentence naming the organising idea and the visible decision it causes. Draw it from what is specific here: the shape of the data, the reader's workflow, the product's mechanism. For example:

- A code review summary ordered by file in diff order, because reviewers read the diff top to bottom.
- A deploy page built on the deploy's timeline, with each step's log opened inline where it failed.
- A settings page grouped by what each change affects, with the consequence written beside the control.

**Swap test.** If the composition would fit an unrelated product with the nouns changed, there is no idea yet. Distinctiveness comes from structure fitted to the content, precise copy in the product's voice, and real data. A new font, colour or effect is decoration, not an idea.

## Compare compositions

Sketch two or three structurally different compositions with the same real content, as grey-box HTML or ASCII at the target width. They differ in hierarchy, reading order, grouping or density; font and colour swaps on one skeleton count as one composition. Pick the one that best serves the ranked content and note what it gives up.

Show the user the alternatives when they asked to choose, when the choice changes product behaviour, or when the trade-off is a preference only they can settle. Otherwise pick and continue.

## Verify

At core step 4, repeat the swap test on the render, and compare the render side by side with each reference on the decision you took from it.

## Report

State the idea, the alternatives, and why the chosen one won.
