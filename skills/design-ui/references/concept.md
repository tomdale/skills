# Concept and alternatives

Use for a new screen, a new visual direction or a redesign. Run it after core step 1 and research.md. It produces the layout core step 2 works from.

## Find the idea

Write one sentence: the organising idea and the visible decision it leads to. Base it on what's specific here: the shape of the data, the reader's workflow, the product's mechanism. For example:

- A code review summary ordered by file in diff order, because reviewers read the diff top to bottom.
- A deploy page built on the deploy's timeline, with each step's log opened inline where it failed.
- A settings page grouped by what each change affects, with the consequence written beside the control.

**Swap test.** If the layout would fit an unrelated product with the nouns changed, you don't have an idea yet. Distinctiveness comes from structure fitted to the content, precise copy in the product's voice, and real data. A new font, colour or effect is decoration.

## Compare layouts

Sketch two or three layouts with the same real content, as grey-box HTML or ASCII at the target width. Make them differ in hierarchy, reading order, grouping or density; different fonts or colours on the same skeleton are the same layout. Pick the one that best serves the ranked content, and note what it gives up.

Show the user the options if they asked to choose, if the choice changes how the product behaves, or if it comes down to a preference only they can make. Otherwise pick one and carry on.

## Verify

In core step 4, run the swap test on the render, and compare it side by side with each reference on the decision you took from it.

## Report

State the idea, the options, and why you picked the one you did.
