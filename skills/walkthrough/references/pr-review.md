# PR review mode

Read this before a GitHub/PR review, PR-feedback or inline-comment request, PR URL/number, or when checkout metadata identifies an active PR. PR review is the local workflow plus `.comment`.

Target: before a walkthrough establish an active checkout PR, supplied URL/number, or enough metadata to identify one. If unavailable, explain that feedback can be drafted but not attached/posted; ask the user to choose local workflow or confirmed PR mode for a later draft. If not a Git repo and no PR, patch, or comparison baseline was supplied, ask for one. Explicit local/self/agent intent overrides an active PR; explicit PR intent selects this mode after target check; otherwise active PR selects it.

Introduction: mode must already be determined before the shared introduction/table is printed. Use that exact Markdown table and include its PR-only final `.comment <text>` / `Record draft PR feedback for later` row. `.todo` actions are handled before questions, comments, and review drafting.

Commands: `.question <text>` records an author question; do not investigate until finish. `.comment <text>` records concise PR feedback, with current-diff location when known; use review-body feedback when no stable locus. `.todo <text>` records a local action/follow-up; at finish complete or resolve it before questions, comments, or draft review. Keep walking after recording unless the user explicitly asks to act now. `.note` remains available but is not in the tutorial. Never automatically record offered questions.

Finish: recap sequence and nonempty notes, then process recorded items in order. (1) Todos: complete/resolve locally. If ambiguous, risky, blocked, or user input is needed, stop and ask; record completed items in `Resolved / Answered`, blocked items in `Todos`. (2) Questions: inspect code, diff, tests, commits, PR description/body; record and move locally answerable items to `Resolved / Answered`; leave author-intent/unavailable facts open. (3) Comments: offer a draft review only now. Unresolved questions become author questions/review-body material; located comments become inline comments; unlocated comments go in review body. Confirm stale, invalid, or ambiguous locations; preview the complete draft. Never post or submit anything without a separate explicit request.
